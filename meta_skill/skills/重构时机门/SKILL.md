# 重构时机门

## 重构评估工作流

触发后，按以下步骤评估：

### 步骤 1：列出现有方案的所有约束

把当前方案中所有的约束、指令、QA 检查、配置项列出来。逐条问：

- 这条约束解决了什么问题？
- 这条约束是否与其他约束冲突？
- 如果删除这条约束，问题会回来吗？

### 步骤 2：判断根因类型

| 根因类型 | 表现 | 应对 |
|---------|------|------|
| **约束战争** | 多个约束互相削弱，模型不知道遵循哪个 | 删除冲突约束，而非新增约束纠正 |
| **结构性耦合** | 两个维度（如布局和颜色）被同一个机制管，改一个影响另一个 | 分离关注点——用不同机制管不同维度 |
| **方案假设过时** | 当前方案的根本假设（如"字号约束能控制输出"、"VLM 能稳定做语义聚合"）已被证伪 | 换路径（如从绝对字号→相对布局、VLM 语义聚合→bbox 几何检测） |
| **复杂度封顶** | 方案复杂度持续增长但效果不增长 | 做减法——删除冗余环节/过时QA/可选配置/合并重叠接口 |
| **层面错配** | 用模糊手段（指令措辞）解决确定性问题（坐标计算/取色位置/字号推导），多轮调整效果不稳定 | 识别问题性质——确定性逻辑用程序化手段，需要理解/创意判断的才用指令 |

### 步骤 3：选择重构动作

按优先级排序：

1. **做减法**：删除过时 QA、冲突约束、可选配置、冗余环节、失败实验方案、合并重叠接口
2. **分离关注点**：把一个耦合的环节拆为两个独立环节（如不同区域用不同机制处理）
3. **换路径**：从一种生成模式切换到另一种（如 t2i→i2i、指令约束位置→程序化后校准、bbox 中心取色→笔画结构取色）
4. **AB 实验**：有多个候选方案时，用 AB 实验而非主观判断决定，实验后删除失败方案

### 步骤 4：向用户确认方向后再动手

输出重构评估结论，等用户确认方向后再开始实现。不要在未确认方向时就开始修改。

## 可执行检查

### 连续失败计数器

在修复同一问题时，追踪已尝试的次数：

```
问题：[问题描述]
第 1 次尝试：[方案] → 结果：[未解决/部分解决/解决但引入新问题]
第 2 次尝试：[方案] → 结果：[同上]
→ 触发重构时机门
```

### 约束冲突扫描

列出当前方案所有约束后，画冲突矩阵：

```
        约束A  约束B  约束C  约束D
约束A    -     冲突   -     -
约束B   冲突    -     -     冲突
约束C    -     -     -     -
约束D    -     冲突    -    -
```

有冲突标记的约束对，至少删除其中一个。

## 通过/失败标准

**通过**：未触发重构条件，或已完成重构评估并确定了新方向。

**失败**：
- 连续 2-3 轮效果不显著（用户反馈或 AI 自评）但仍在继续微调
- 做加法引入了退化但仍在继续增加约束
- 用户纠正了方向但未停下来重新理解需求
