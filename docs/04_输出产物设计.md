# 输出产物设计

## 运行目录

每次执行应使用独立输出目录，避免旧结果污染本次分析。`output/` 属于生成目录，不进入版本控制。

## 组织阶段产物

`distill.py` 生成：

```text
<run_dir>/
├── anchor_recent.md
├── session_index.md
└── ANALYSIS_INSTRUCTION.md
```

- `anchor_recent.md`：按 session 边界保存实际选中的最近 N 个完整锚点。
- `session_index.md`：包含全部候选 session 的 id、工具、项目、源文件、turn 数和首条用户输入。
- `ANALYSIS_INSTRUCTION.md`：独立可执行的 Phase 3-7 分析合同。

## 第一层蒸馏产物

```text
<run_dir>/
├── action-guides/
├── error-patterns/
├── repeated-requirements/
├── conflicting-requirements/
└── related-findings/
```

每个发现必须包含可追溯证据：至少记录 `session_id` 和 `turn_index`，或引用包含这些字段的结构化证据文件。

最低完整性要求：

- 至少一个行动指南；
- 至少一个错误模式，且包含根因；
- 重复要求明确标记“有”或“未发现”；
- 冲突/变更要求明确标记“有”或“未发现”；
- 关联发现覆盖五个关联维度，或逐项说明无证据；
- 所有跨 session 结论保持来源边界。

## 第二层技能合成产物

```text
<run_dir>/skill-synthesis/
```

该目录只在第一层完整性检查通过后生成，包含：

- 更新已有技能的具体差异；
- 新技能目录及 `SKILL.md`；
- 不应转成技能的项目知识或被动规则及理由；
- `skill-creator` 验证和技能健康检查结果。

## 自动 QA

```bash
python3 scripts/validate_run.py <run_dir>
python3 scripts/validate_run.py <run_dir> --first-layer
```

组织阶段 QA 为阻断式检查：缺文件、session 标记不配对、id 不一致、索引缺项或阶段编号错误时返回非零退出码。`--first-layer` 还会检查五类产物目录、非空文件和 session/turn 证据；无结果的类别必须明确写出“未发现”或“无证据”。
